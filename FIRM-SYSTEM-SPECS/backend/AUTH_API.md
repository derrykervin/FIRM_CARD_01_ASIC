# 后端接口与迁移
主仓库未确认，以下未集成。
POST /v1/auth/steam：通过Steam官方服务端票据验证接口验证票据、AppID与SteamID，再按官方所有权接口/策略核验授权；服务器保管Web API密钥。不信任Unity上传的SteamID或Reader pass。
POST /v1/cards/challenges：已验证Steam会话、卡状态和绑定授权后生成一次性挑战。
POST /v1/cards/proofs：验签并在事务内原子消费挑战；会话签发前复查封禁/所有权/绑定版本。过期/重复/换账号/换卡证明拒绝。
POST /v1/cards/unbind：重新认证、权限检查、审计和会话撤销；不要仅凭UID解绑。
POST /v1/reader/events：插拔是可伪造客户端事件，仅用于体验和撤销请求，不能独立授予权限。轮询/心跳和过期策略应处理丢失拔卡事件。
会话：短期access token（建议5分钟）、旋转refresh token、服务器撤销表/会话版本，解绑挂失立即撤销。资源清单含版本、大小、SHA256和可信签名；缓存命中仍校验manifest授权，哈希不是授权。
迁移顺序：找到仓库→Steam沙箱票据测试→SQL约束迁移→挑战原子消费→安全器件互通→Unity登录和拔卡回归→灰度发布。
